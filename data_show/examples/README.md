# 範例訴願書 PDF(上傳測試用)

供上傳到訴願 AI 系統做實測用的 2 份範例訴願書 PDF。內容取自
`mock_data/sample_appeals/` 內既有測資的 `appeal_text` 欄位,以 PyMuPDF(fitz)
渲染成一般 A4 直式訴願書格式,可直接上傳或複製內文貼上測試。

## 檔案清單

| 檔案 | 素材來源 | 案由 | 預期結果 |
|---|---|---|---|
| `範例1_不受理_訴願逾期.pdf` | `sample_appeals/b_overdue_77_2.json` | 廢棄物清理法裁罰案件,訴願人主張未及時知悉原處分 | **不受理**(訴願法第77條第2款,訴願逾法定期間) |
| `範例2_受理_廢棄物清理法.pdf` | `sample_appeals/d_dismiss_waste.json` | 廢棄物清理法裁罰案件(未依規定使用專用垃圾袋),訴願人主張無違規故意 | **受理**進入實體審查,審理結果為**駁回**(訴願法第79條第1項,訴願無理由) |

> 「受理」是指系統的訴願程式審查(screening)通過、進入實體審理階段,
> 與最終「駁回」(維持原處分)是兩個不同層次的結果,兩者不衝突:
> 範例2 程式上受理,但實體審理後駁回訴願人之主張。

## 內容摘要

**範例1(不受理)**：訴願人黃○毅因違反廢棄物清理法,不服新北市政府環境保護局
110年8月31日裁處書,主張長年在外地工作、未能及時知悉原處分內容而遲至111年
11月10日始提起訴願。因原裁處書已合法公示送達,訴願人提起已逾30日法定不變
期間,應依訴願法第77條第2款為不受理決定。

**範例2(受理)**：訴願人陳○瑤因違反廢棄物清理法(未依規定使用專用垃圾袋、
未依規定時間地點交付垃圾清除),不服新北市政府環境保護局110年10月26日裁處書
(罰鍰新臺幣3,600元),主張係遛狗順手撿拾其他犬隻排泄物置入社區垃圾袋,並無
違規故意,請求撤銷或從輕發落。因訴願書已於法定期間內提起、無訴願法第77條各款
不受理事由,應予受理進行實體審查。

## 用法

1. **上傳測試**：直接將 PDF 檔上傳到訴願 AI 系統(系統以 PyMuPDF 抽取 PDF 文字
   後送 Bedrock 分析)。
2. **文字貼上測試**：亦可開啟對應的 `sample_appeals/*.json`,複製其
   `appeal_text` 欄位內容,直接貼到系統的文字輸入框測試,效果與上傳 PDF
   應一致。

## 產生方式

由 `gen_examples.py` 產生,執行方式：

```bash
python gen_examples.py
```

腳本會讀取上述兩個 JSON 的 `appeal_text`,以 PyMuPDF 繪製 A4 直式 PDF(標題
「訴願書」+ 內文,採微軟正黑體並做字型子集化以縮小檔案),產生後另外用
`fitz.open(...).get_text()` 重新開啟每個 PDF 驗證可正確抽出中文,驗證結果
寫入 `verify_log.txt`。

### 字型說明

原計畫使用 PyMuPDF 內建 CJK 字型 `china-t`,但實測發現該內建字型雖可正常
「顯示」中文,卻未提供 ToUnicode CMap,導致 `get_text()` 抽取出來的內容是
亂碼、無法被系統的 PyMuPDF 文字抽取流程正確讀取。因此改用系統內嵌真實
TrueType 字體(`C:\Windows\Fonts\msjh.ttc`,微軟正黑體)嵌入 PDF,顯示與文字
抽取皆正確;另外做了 `subset_fonts()` 子集化,避免整包字型集合(約 20MB)被
內嵌導致檔案過大。
