# 開箱示範素材(三槽上傳測試用)

`POST /api/cases` 三個槽位(訴願書／送達證書／原處分書)全部必填,所以示範素材也是
**每案三份 PDF**。無 AWS 憑證、無 Gemini 金鑰的 mock 模式下,把一個案件資料夾裡的三份 PDF
分別拖進三個槽位,即可一路跑到決定書草稿 PDF 下載。

## 檔案清單

| 資料夾 | 對應 mock 樣本 | 卷內事實 | 預期結果 |
|---|---|---|---|
| `範例1_不受理_寄存送達逾期/` | `sample_appeals/g_overdue_77_2_deposit.json` | 裁處書 110/9/20 寄存於板橋郵局送達,機關收文 111/11/14 | **不受理**(訴願法§77(2)):期間算式末日 110/10/20,已逾期 |
| `範例2_受理駁回_廢棄物清理法/` | `sample_appeals/d_dismiss_waste.json` | 裁處書 110/10/28 本人收受,機關收文 110/11/15 | **受理**進入實體審理(末日 110/11/27 為週六順延至 11/29,未逾期),審理結果**駁回** |
| `送達證書變體/` | (測資,不是完整案件) | 見下節 | 供抽取層的邊界測試用 |

每個案件資料夾內固定三個檔名:`01_訴願書.pdf`、`02_送達證書.pdf`、`03_原處分書.pdf`。

> 「受理」指程序審查(screening)通過、進入實體審理,與最終「駁回」(維持原處分)是兩個層次,
> 兩者不衝突:範例2 程序上受理,實體審理後駁回。

### 寄存送達為什麼是寄存當日生效

行政程序法§74 未規定等待期,法務部函釋與釋字 797 均認寄存送達於**寄存日**即生效,
**不加 10 日**(依據見 `data/output/階段一文書規格與期間計算.md` §零「錯誤 1」)。
範例1 的末日就是照這個算法算出來的:寄存 110/9/20 → 起算 9/21 → 30 日 → 10/20。

## 送達證書的兩種變體

實際填寫過的送達證書掃描檔取不到(涉個資,制度性不公開),**手寫與戳記的落字方式沒有實據**。
這個未知消不掉,但可以圈起來——除了照官方範本填寫的標準件,另做兩種變體當測資:

| 檔案 | 模擬什麼 | 系統應有的行為 |
|---|---|---|
| `變體1_送達證書_日期寫在格線外.pdf` | 手填常見:「送達時間」欄名與年月日不同行 | **抽得到**送達日,不退用訴願人自述日 |
| `變體2_送達證書_僅有郵局日戳.pdf` | 交郵版最常見:「送達時間」空白,日期只在郵局日戳 | **回報抽不到**並退用自述日 ＋ 標記待人工;**不得拿日戳當送達時間**(兩者在法律上不是同一件事) |

變體2 的日戳日期(110/9/18)刻意與訴願人自述日(110/9/20)不同——猜值的話末日會整整差兩天,
這條差異就是測試抓得到「有沒有偷猜」的地方。守門測試在
`backend/tests/test_demo_examples.py`。

## 產生方式

```bash
cd data_show/examples
python gen_examples.py
```

文書原文在 `demo_documents.py`(欄位名逐字取自官方範本:送達證書取法務部「行政文書交郵
送達證書」與臺北市自行送達證書格式,訴願書取新北市法制局範本,原處分書依行政程序法§96 I
六款)。`gen_examples.py` 只負責排版成 A4 PDF,產生後逐檔重新抽字驗證,結果寫入
`verify_log.txt`。

### 字型說明

PyMuPDF 內建 CJK 字型 `china-t` 雖可正常「顯示」中文,卻沒有 ToUnicode CMap,
`get_text()` 抽出來是亂碼。故改為內嵌系統 TrueType(`C:\Windows\Fonts\msjh.ttc`,
微軟正黑體)並做 `subset_fonts()` 子集化,顯示與抽字皆正確,檔案也不會被整包字型集合
(約 20MB)撐大。`test_demo_examples.py` 有一條測試專門守這件事
(可讀字元比例 > 0.9),換字型時它會先叫。
